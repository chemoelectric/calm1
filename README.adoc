== calm1: a macro-preprocessor to reduce your anxieties

This macroprocessor runs in R⁷RS Scheme. The accompanying GNUmakefile
is for building, installing, and testing with CHICKEN 6. The source
code can easily be included with a project, to be run in an
interpreter such as Gauche, Chibi, or Sagittarius.

[cols="2,3"]
|===
|+(@ eval FORM ...)+  +
+(@ hide FORM ...)+  +
+(@ dnl FORM ...)+

|Evaluate +FORM+{nbsp}+...+ as Scheme. The “+eval+” version expands
 the results, whereas “+hide+” does not. The “+dnl+” version not only
 hides the results, it deletes text up through the next newline.

|+(@ when PREDICATE FORM ...)+  +
+(@ unless PREDICATE FORM ...)+

|For “+when+”, re-insert the evaluated results of +FORM+{nbsp}+...+ if
 +PREDICATE+ evaluates as true in Scheme. For “+unless+”, reverse the
 sense of the +PREDICATE+.

|+(@ if FORM ...)+  +
+(@ while FORM ...)+

|Nondeterministic branching and looping. These do not reinsert
 anything automatically, because it would be difficult to control
 reinsertion (especially by “while”) if they did. Incidentally, you
 can make the branching and looping deterministic by putting the all
 the logic in Scheme code within a single macro-branch.

If you want the output of +(@ while ...)+ expanded recursively, you
must use +@in+ to reinsert iteratively generated parts _in reverse_.
Alternatively, you can collect the parts into a Scheme structure and
reinsert them all at once as a string.

|+(@ include-raw FORM ...)+  +
+(@ include FORM ...)+

|Include the files specified by +FORM+{nbsp}+...+. The “+include-raw+”
 version outputs the file contents verbatim. The “+include+” version
 inserts the file contents into the macroprocessing stream.

|+(@ define MACRO-NAME MACRO-BODY)+  +
+(@ pushdef MACRO-NAME MACRO-BODY)+

|Define a macro with the name given by the form +MACRO-NAME+ and
 definition by the form +MACRO-BODY+, which (in the current
 implementation) must evaluate to a string. When a macro call is made,
 +MACRO-BODY+ is inserted and then evaluated recursively. The
 “+define+” version pops any top definition of the macro, whereas
 “+pushdef+” does not.

|+(@ popdef MACRO-NAME ...)+

|Pop definitions.

|+(@ undefine MACRO-NAME ...)+

|Remove all definitions corresponding to the given macro names.

|+(@defn MACRO-NAME)+

|Scheme to return the macro handler for +MACRO-NAME+. This macro
 handler can be used as the +MACRO-BODY+ for +(@ define ...)+ or +(@
 pushdef ...)+.

|+(@out FORM)+

|Scheme to try to convert +FORM+ to a string and output it.

|+(@in FORM)+

|Scheme to try to convert +FORM+ to a string and prepend it to the
 input (“reinsert it”).

|+(@drop NUMBER)+

|Scheme to drop +NUMBER+ code points from the front of the input. If
 there are fewer code points remaining, the input is emptied.

|++($a := (* ($a) (+ ($b) 1)))++

|Scheme operations using variables. Predefined variables include +$a+
 to +$z+ and +$A+ to +$Z+.

|===

There are a lot of things you can do that are undocumented. The code
is meant to be hacked on and specialized for a particular project. The
same thing was said about TeX, but calm1 is a small Scheme project.

The project appears larger than it actually is, because it includes
other reüsable source codes, including:

+(calm1-lib define-record-factory)+:: This is a copy of the R⁷RS
implementation of +define-record-factory+, my version of Scheme
records. I also have implementations for R⁶RS, +er-macro-transformer+,
and Gambit Scheme.

+(calm1-lib snobol-match)+:: SNOBOL4/SPITBOL-like string processing
for R⁷RS Scheme. The library works with UTF-32 stored as R⁶RS-style
bytevectors.

+(calm1-lib snobol-char-set)+:: Character set support for +(calm1-lib
snobol-match)+.
