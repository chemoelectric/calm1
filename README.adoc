== calm1: a macro-preprocessor to reduce your anxieties
=== Introduction

This macroprocessor runs in R⁷RS Scheme.
The accompanying ++calm1.egg++
and ++GNUmakefile++ files are for compiling, installing, and testing
with CHICKEN 6. The source code can easily be included with any kind
of project, to be compiled with CHICKEN or run in an interpreter such
as Gauche, Chibi, or Sagittarius.

Frequent use of a macroprocessor helps you worry less about errors.
Try it and see.

=== Syntax
[cols = "3,4"]
|===

|++(@ eval FORM ...)++   +
++(@ hide FORM ...)++   +
++(@ dnl FORM ...)++

|❧ __Evaluation of__
++FORM ...++ __as Scheme.__
The “++eval++” version
expands the results, whereas “++hide++” does not. The
“++dnl++” version not only hides the results, it deletes
text up through the next newline.



|++(@ when PREDICATE FORM ...)++   +
++(@ unless PREDICATE FORM ...)++

|❧ __Deterministic branching.__
For “++when++”, reïnsert the evaluated results of
++FORM ...++
if ++PREDICATE++ evaluates as true in Scheme.
For “++unless++”,
reverse the sense of the ++PREDICATE++.



|++(@ if FORM ...)++   +
++(@ while FORM ...)++

|❧ __Nondeterministic branching and looping.__
The author favors Edsger W. Dijkstra’s nondeterministic branching and
looping. Nondeterminism is by default enforced with a
well seeded random number
generator, to help you catch your errors. The “++if++”
and “++while++” macros do not reïnsert
anything automatically, primarily because otherwise it would
be very difficult to control reïnsertion by “++while++”.
  +
⁠ If you want the output of ++(@ while ...)++
expanded recursively, you must use ++@in++ to
reïnsert iteratively generated parts __in reverse__. Alternatively,
you can collect the parts into a Scheme structure (such as a string or
string port) and reïnsert them all at once as a string. You could use
a named pipe or other means, too.
  +
⁠ You can make the branching and looping deterministic
by writing only one ++FORM++ and putting all the branching logic in
Scheme.



|++(@ include-raw FORM ...)++   +
++(@ include FORM ...)++

|❧ __Inclusion of file contents or command output.__
Include the files specified by ++FORM ...++.
The “++include-raw++”
version outputs the file contents verbatim. The “++include++” version
inserts the file contents into the macroprocessing stream.
  +
⁠ If instead of a filename a ++FORM++
 is a string ending in a “&#x7C;”
character, the inclusion is taken from the output of the shell command
obtained by removing the final “&#x7C;” character.
This capability is not
present if the ++--safer++ option is used.



|++(@ define MACRO‑NAME MACRO‑BODY)++   +
++(@ pushdef MACRO‑NAME MACRO‑BODY)++

|❧ __Macro definition.__
Define a macro with the name given by the form ++MACRO‑NAME++ and
 definition by the form ++MACRO‑BODY++, which (in the current
implementation) must evaluate to a string. When a macro call is made,
++MACRO‑BODY++ is inserted and then evaluated recursively. The
“++define++” version pops any top definition of the macro, whereas
“++pushdef++” does not.



|++(@ popdef MACRO‑NAME ...)++

|❧ __Macro definition pop.__
Remove the most recent macro definition for each given name.



|++(@ undefine MACRO‑NAME ...)++

|❧ __Macro definition removal.__
Remove all macro definitions corresponding to the given macro names.



|++(@defn MACRO‑NAME)++

|❧ __Macro definition retrieval.__
Scheme to return the macro handler for ++MACRO‑NAME++.
This macro
handler can be used as the ++MACRO‑BODY++ for
++(@ define ...)++ or
++(@ pushdef ...)++.



|++(@out FORM)++   +
++(@out FORM PORT)++

|❧ __Outputting text.__
Scheme to try to convert ++FORM++
to a string and output the string.



|++(@outs FORM)++   +
++(@outs FORM PORT)++

|❧ __Outputting an s-expression.__
Scheme to try to convert ++FORM++
to an s-expression string and output the string.



|++(@in FORM)++

|❧ __Reïnserting text.__
Scheme to try to convert ++FORM++
to a string and prepend the
string to the input (“__reïnsert__” it).



|++(@ins FORM)++

|❧ __Reïnserting an s-expression.__
Scheme to try to convert ++FORM++
to an s-expression string and
prepend the string to the input
(“__reïnsert__” it).



|++(@drop NUMBER)++

|❧ __Skipping some of the input.__
Scheme to drop ++NUMBER++ code points from the front of the input. If
there are fewer code points remaining, the input is emptied.



|++($a := (* ($a) (+ ($b) 1)))++

|❧ __Imperative variables for use in Scheme.__
The predefined variables are ++$a++
to ++$z++ and
++$A++ to ++$Z++.




|===

=== Miscellaneous

The code is meant to be easy to hack on and specialize for a particular
project. There are already a lot of things you can do that are
undocumented above. For instance, a great amount of Scheme is included
in the environment in which macroprocessing is done. It is all
available.

The project appears larger than it actually is, because it includes
other reüsable source codes. The author copies such codes from project
to project and considers them freely hackable. Included are:

==== Module: (calm1-lib define-record-factory)

This is a copy of the R⁷RS
implementation of ++define-record-factory++,
the author’s version of
Scheme records. (Elsewhere there are various versions for R⁶RS,
++er-macro-transformer++, and Gambit Scheme’s version of
++syntax-case++.)

==== Module: (calm1-lib snobol-match)

SNOBOL4/SPITBOL-like string processing
for R⁷RS Scheme. The library works with UTF-32, which is stored
internally as R⁶RS-style bytevectors. This style of bytevector is
supported in R⁷RS-large as
++(except (scheme bytevector) bytevector-copy!)++
and in the CHICKEN ++r6rs-bytevectors++
egg as
++(r6rs bytevectors)++. There is included a test program
++calm1-lib/test-snobol-match.scm++.

==== Module: (calm1-lib snobol-char-set)

Character set support for ++(calm1-lib snobol-match)++.
There is included a test program
++calm1-lib/test-snobol-char-set.scm++.
